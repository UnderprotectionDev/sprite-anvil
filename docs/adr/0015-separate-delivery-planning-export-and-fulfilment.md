# Separate delivery planning, export evidence, and fulfilment

A Delivery Target is a versioned plan that pins its Context Revision, Required Set revisions, and target policies without pinning exact Asset Versions; an Export Bundle is immutable evidence of one generated package; and a Delivery Fulfilment is the user-finalized mapping from a target's requirements to the exact bundles and versions actually delivered. Target Readiness is therefore computed separately from Delivery Status, and multi-bundle overlaps must be resolved explicitly instead of using an implicit newest-wins rule. This preserves the meaning of plans and historical deliveries while supporting incremental, multi-package releases, at the cost of additional states, mappings, and a human finalization gate.
