# Use extensible asset support levels

Every asset category will receive General Asset Support, while an explicit core set receives Specialized Asset Profiles: character/creature and animation; object/weapon/equipment and state families; icons; VFX/projectile/shadow/decal; tileset/terrain and seamless texture; background/parallax; UI screens and components; and portrait/logo/marketing art. Fonts, cursors, and auxiliary maps initially remain at General Asset Support. A profile is not complete merely because it has dedicated UI: it must define required and optional production metadata, Integrity Gates, Waivable Requirements, Quality Advisories, human review tasks, usage-context tests, export mappings, and an end-to-end Reference Acceptance Scenario on web and desktop. Each Asset Family carries a versioned Required Set of required, optional, and inapplicable inventory; a new Required Set revision recomputes current completion without altering historical completion evidence, and completion means every required item is current and Export Ready rather than conforming to one universal animation or state list. This preserves broad project coverage without making every example category a bespoke-workspace completion dependency, at the cost of building and maintaining an explicit support and acceptance contract for every specialized family.
