# Scope semantic distinction by use

For feature candidate F1, Semantic Distinction Requirements belong to declared use conditions rather than applying universally to the same meanings throughout a project; common expectations may be reused. The user may make a Semantic Distinction Review a Delivery Target acceptance condition, in which case missing or failed required review prevents readiness, while automated visual suspicions alone do not; this accommodates deliberate ambiguity in one scene and required clarity in another, at the cost of explicit use-scoped expectations and review evidence. The original 2026-09-21 opportunity-interview file is unavailable, so it is not cited as recoverable evidence; this ADR preserves the accepted decision and does not add F1 to the PRD's required scope.

A failed required review has no separate acceptance waiver: the user must correct and reassess the work or explicitly revise the target or requirement scope in a new revision. Existing Quality Waivers are not extended to subjective review outcomes, and changing the delivery scope does not rewrite the failed evidence; this keeps exceptions explicit at the cost of revising scope for an intentionally relaxed delivery.
