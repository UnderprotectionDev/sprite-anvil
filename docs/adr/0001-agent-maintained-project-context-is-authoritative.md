# Agent-maintained project context is authoritative

The Workbench will treat the project's agent-maintained, human-readable `context.md` as the authoritative source for scoped visual rules, exceptions, and production decisions. Provider-neutral Context Agents use a versioned Context Agent Contract to author schema-validated, identity-bearing Context Rules and free-form rationale as Context Proposals; they cannot activate their own changes, and the user does not directly edit the document but reviews and activates proposals as Context Revisions. Every proposal names its base revision: independent rule changes may merge semantically, but overlapping rule or scope changes require user resolution. Inheritance follows operation, asset, asset family, theme, visual world, then project, while a more specific rule replaces an inherited rule only through an explicit Context Override and contradictions within one scope block activation. Style Modules group and version style rules inside Project Context and may be copied between projects, but no separately authoritative live Style Pack exists. This removes manual document maintenance and provider lock-in while preserving human authority and a portable source of truth, at the cost of agent-contract versioning, validation, provenance, semantic diff, and conflict-resolution machinery.
